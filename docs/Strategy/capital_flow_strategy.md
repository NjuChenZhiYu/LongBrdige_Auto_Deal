# 个股资金流与流动性承接策略设计

## 1. 目标

本文用于重构单股分析中的“资金流”模块。目标不是继续停留在“主力净流入为正就看多、为负就看空”的简单逻辑，而是把个股交易行为拆成四个层次：

1. **方向**：资金到底在流入还是流出。
2. **承接**：盘口有没有真实成交支撑。
3. **相对热度**：当前活跃度相对过去 1 个月、3 个月处于什么位置。
4. **变化方向**：活跃度是在升温、降温，还是处于冰点修复阶段。

因此，本模块的核心定位应从“资金流标签器”升级为“**资金方向 + 流动性承接 + 热度导数** 的综合中间层”。

---

## 2. 为什么原方案不够

旧方案的优点是简单、直观，但存在三个明显问题：

1. **只看净流方向，忽略承接质量**
   - `main_in_flow > 0` 只能说明主力净额为正，不代表市场就有足够承接。
   - 如果成交额和换手率都很低，所谓“流入”可能只是极小流通盘里的局部撮合，并不足以支持趋势。

2. **只看静态值，忽略相对位置**
   - 同样是 `10 亿成交额`，对腾讯和对小市值新股的含义完全不同。
   - 同样是 `5% 换手率`，对日常高换手题材股和低换手权重股的含义也完全不同。
   - 必须把当前值与过去 `20日 / 60日` 进行比较，才能知道这是“异常放大”还是“正常波动”。

3. **只看热度高低，忽略导数**
   - 市场热度高，不一定是买入信号，可能是高位末端加速。
   - 市场情绪冰点，也不一定是卖出信号，可能是左侧谷底区域。
   - 所以不能只判断“高 / 低”，还要判断“升温 / 降温 / 衰减 / 修复”。

---

## 3. 模块边界

本文只讨论**个股层**的资金与流动性承接，不覆盖市场层和板块层流动性。

边界建议如下：

1. `docs/Strategy/market_capital_flow.md`
   - 负责市场层、板块层、个股层的总框架
   - 负责 `market_score / sector_score / stock_score` 的上游定义

2. 本文档 `docs/Strategy/capital_flow_strategy.md`
   - 负责个股层的“资金流 + 成交承接 + 热度变化”的具体算法
   - 作为 `stock_score` 的主要来源文档

换句话说，本文件是 `stock_score` 的方法论说明书。

---

## 4. 核心原则

### 4.1 不把“资金净流”误当成“流动性”

个股分析必须把两类问题拆开：

1. **资金方向**
   - 看 `main_in_flow`、`in_flow`
   - 回答：钱是净流入还是净流出

2. **流动性承接**
   - 看 `turnover`、`turnover_rate`
   - 回答：有没有足够的真实成交承接

结论：

- `资金流` 负责判断“方向”
- `成交额 + 换手率` 负责判断“承接质量”

缺一不可，不能互相替代。

### 4.2 不用单一指标做线性判断

以下几种线性推理都容易出错：

1. 成交额高 = 买入
2. 换手率高 = 强势
3. 主力净流入 = 必涨
4. 冰点 = 必卖
5. 热度高 = 必追

更合理的判断方式是：

1. 先看方向
2. 再看承接
3. 再看相对位置
4. 最后看导数

## 5. 输入数据与字段来源

## 5.1 资金流字段

来自 `get_capital_flow(...)`：

1. `in_flow`
2. `main_in_flow`
3. `capital_flow_item_time`
4. `super_in_flow`
5. `big_in_flow`
6. `mid_in_flow`
7. `sml_in_flow`

### 用途

1. 重点判断**整体净流入/净流出方向**，即 `in_flow`
2. 辅助判断**主力净流方向**，即 `main_in_flow`
3. 判断整体与主力是否一致
4. 粗粒度识别是主力托底、主力出逃，还是市场分歧

### 关于 `super/big/mid/sml` 的使用原则

这几个字段可以保留，但在策略上应**弱化权重**，原因是：

1. 主力、游资、机构完全可能拆分成多个账户下单
2. 单笔口径并不稳定，容易被“拆单行为”污染
3. 若过度依赖 `big / mid / sml` 的静态拆分，容易把执行层噪声误判成真实资金属性

因此建议：

1. **主判断**
   - `in_flow`
   - `main_in_flow`

2. **辅助判断**
   - `super_in_flow / big_in_flow / mid_in_flow / sml_in_flow`

3. **不建议**
   - 仅凭 `big_in_flow` 或 `mid_in_flow` 的正负，直接给出“机构进场 / 散户出逃”结论

换句话说，本模块默认采用“**先看 in 还是 out，再看 main 是否同向**”的粗粒度判断，不把订单大小拆分当作绝对真相。

## 5.2 成交承接字段

来自快照或 K 线：

1. `turnover`
2. `turnover_rate`
3. `volume`
4. `close`
5. `high`
6. `low`

### 用途

1. `turnover` 看绝对成交规模
2. `turnover_rate` 看筹码交换效率
3. `volume` 仍可保留作为辅助项，但不再作为唯一量能标准

---

## 6. 今日数据使用边界

这是本模块最重要的实务约束之一。

### 6.1 港股当天 `turnover / turnover_rate` 不能过早纳入正式比较

港股盘中累计成交额和累计换手率，在收盘前具有天然不完整性：

1. 早盘数据天然偏低
2. 午盘前后不可横向比较
3. 尾盘放量是港股常见现象

因此，盘中若直接把“今天的成交额/换手率”与历史日线完整数据做比较，会系统性低估热度。

### 6.2 统一规则

建议沿用现有逻辑：

1. 港股 `15:00` 前：
   - 不使用当天 `turnover`
   - 不使用当天 `turnover_rate`
   - 默认用最近一个完整交易日作为比较目标

2. 港股 `15:00` 后：
   - 若 `update_time / data_date / last_trade_time` 确认是当日
   - 才允许把当天 `turnover / turnover_rate` 纳入正式对比

### 6.3 设计含义

这不是“数据保守”，而是为了防止以下误判：

1. 早盘误判成缩量
2. 午盘误判成流动性枯竭
3. 盘中把尚未完成的换手率错误解释成“无人接盘”

## 7. 指标框架

## 7.1 第一层：资金方向指标

这一层只回答“谁在买、谁在卖”。

### 建议指标

1. `total_flow_today_ratio = in_flow_today / circular_market_val`
2. `main_flow_today_ratio = main_in_flow_today / circular_market_val`
3. `total_flow_5d_ratio = total_in_flow_5d / circular_market_val`
4. `main_flow_5d_ratio = main_in_flow_5d / circular_market_val`
5. `main_flow_10d_ratio = main_in_flow_10d / circular_market_val`
6. `main_flow_90d_ratio = main_in_flow_90d / circular_market_val`
7. `main_vs_total_consistency`

### 解释逻辑

1. 整体、主力同向流入：更像真实承接
2. 整体流出、主力流入：更像主力托底，市场仍有分歧
3. 整体流入、主力流出：更像表面热闹、内在派发
4. 长短周期同时流入：更有趋势意义
5. 若只有 `big/mid/sml` 某一项异动，而 `in_flow` 与 `main_in_flow` 不确认，不做强结论

---

## 7.2 第二层：成交承接指标

这一层回答“有没有真实流动性支持”。

### 为什么要同时看成交额和换手率

1. 只看 `turnover`
   - 大市值股票天然更大
   - 横向可比性差

2. 只看 `turnover_rate`
   - 小盘股容易异常高换手
   - 很容易把情绪扰动误判成有效承接

因此必须组合使用：

1. `turnover` 看绝对成交规模
2. `turnover_rate` 看筹码交换效率

### 建议指标

1. `turnover_ratio_20 = target_turnover / ema20(turnover)`
2. `turnover_ratio_60 = target_turnover / ema60(turnover)`
3. `turnover_rate_ratio_20 = target_turnover_rate / ema20(turnover_rate)`
4. `turnover_rate_ratio_60 = target_turnover_rate / ema60(turnover_rate)`

### 含义

1. `ratio > 1`：高于历史均值
2. `ratio < 1`：低于历史均值
3. `20日`：更偏近 1 个月热度
4. `60日`：更偏近 3 个月热度位置

注意：

- `5/20` 适合短线量能 regime
- `20/60` 更适合“过去 1 月 / 3 月的相对位置”判断

---

## 7.3 第三层：导数与热度变化

这一层回答“热度是在升温还是降温”。

### 核心原因

单看热度高低容易误判：

1. 高热度可能是主升浪，也可能是最后一冲
2. 低热度可能是无人问津，也可能是下跌末端

因此必须引入导数概念。

### 建议指标

1. `turnover_ema20_slope = pct_change(ema20(turnover))`
2. `turnover_rate_ema20_slope = pct_change(ema20(turnover_rate))`
3. `turnover_ema5_vs_ema20 = ema5(turnover) / ema20(turnover)`
4. `turnover_rate_ema5_vs_ema20 = ema5(turnover_rate) / ema20(turnover_rate)`

### 解释逻辑

1. 热度高且导数继续抬升
   - 说明增量交易仍在强化

2. 热度高但导数开始回落
   - 更像高位降速或末端衰减

3. 热度低但导数止跌回升
   - 更像冰点修复或谷底候选

4. 热度低且导数继续向下
   - 更像弱势延续，而不是左侧机会

### `heat_phase` 建议计算逻辑

`heat_phase` 不是一个单独指标，而是由“相对位置 + 导数 + 价格位置”联合给出的阶段标签。第一版建议只保留少量阶段，不要过拟合。

#### 输入变量

1. `turnover_ratio_20`
2. `turnover_ratio_60`
3. `turnover_rate_ratio_20`
4. `turnover_rate_ratio_60`
5. `turnover_ema20_slope`
6. `turnover_rate_ema20_slope`
7. 当前价格位置（高位 / 中位 / 低位）

#### 建议规则

1. **过热扩张**
   - `turnover_ratio_20 > 1.2`
   - `turnover_rate_ratio_20 > 1.2`
   - 且至少一个 slope > 0
   - 且价格处于中高位

2. **过热衰减**
   - `turnover_ratio_20 > 1.2` 或 `turnover_rate_ratio_20 > 1.2`
   - 但 `turnover_ema20_slope <= 0` 且 `turnover_rate_ema20_slope <= 0`
   - 且价格处于高位

3. **低位冷区修复**
   - `turnover_ratio_20 < 1.0`
   - `turnover_rate_ratio_20 < 1.0`
   - 但 slope 由负转平或转正
   - 且价格处于低位

4. **弱势延续**
   - `turnover_ratio_20 < 1.0`
   - `turnover_rate_ratio_20 < 1.0`
   - 且两个 slope 均 <= 0
   - 且价格仍在下行结构

5. **中性整理**
   - 其余情况统一归入中性整理

#### 重要说明

1. `heat_phase` 只是帮助描述当前活跃度阶段，不直接等同买卖信号
2. 同样的 `低位冷区修复`，若主力净流仍持续为负，也不能直接看多
3. 同样的 `过热扩张`，若价格仍未脱离关键压力位，也不能盲目追高

---

## 7.4 第四层：价格位置联动

资金流和量能不能脱离价格位置单独解读。

### 必须联动的价格信息

1. 当前涨跌幅
2. 短期趋势标签
3. `bias20`
4. 布林位置
5. POC / 筹码分布
6. 多周期位置

### 典型场景

1. 高位 + 放量 + 主力流出
   - 更像派发

2. 低位 + 缩量 + 主力不再流出
   - 更像抛压衰减

3. 低位 + 热度回升 + 导数转正 + 主力净流入
   - 更像左侧修复向右侧转化

4. 高位 + 热度极高但导数转弱
   - 更像末端诱多风险

---

## 8. 输出层不要过拟合

## 8.1 保留简单 regime

当前代码中已有：

1. `放量`
2. `中性`
3. `缩量`

这个输出层设计应保留，不建议在第一版把中性拆得过细。

原因：

1. 中性状态本来就信息含量有限
2. 强行解释会放大量化噪声
3. 真正有交易价值的是“明显偏离”，不是“所有状态都要有故事”

### 第一版建议

1. `放量`
   - 仅在当前值相对基线显著抬升时触发

2. `缩量`
   - 仅在当前值相对基线显著回落时触发

3. `中性`
   - 直接透传，不做过度二次包装

---

## 8.2 旧的量能标签逻辑如何调整

现有代码里，`5/20` 主要用于：

1. 短线量能偏离检测
2. 与价格标签做二次联动

这个逻辑不必废弃，但要明确定位：

1. `5/20`
   - 负责短线 `volume_regime`

2. `20/60`
   - 负责热度位置与中期比较

3. 导数
   - 负责判断是升温、降温还是冰点修复

也就是说，后续代码结构应是“**短线 regime + 中期位置 + 导数判断**”三层并存，而不是互相替代。

## 9. 标签体系建议

本模块最终不建议直接输出大量复杂标签，而建议输出“结构化字段 + 少量标签”。

### 建议输出

```json
{
  "capital_flow_profile": {
    "flow_label": "主力托底但市场分歧仍大",
    "volume_regime": "缩量",
    "main_flow_today_ratio": 0.0021,
    "main_flow_5d_ratio": 0.0078,
    "turnover_ratio_20": 0.84,
    "turnover_ratio_60": 1.12,
    "turnover_rate_ratio_20": 0.91,
    "turnover_rate_ratio_60": 1.18,
    "turnover_ema20_slope": 0.7,
    "turnover_rate_ema20_slope": 0.5,
    "heat_phase": "低位冷区修复中",
    "summary": "主力并未显著出逃，短线成交仍偏弱，但相对 3 个月基准已有改善，接近抛压衰减后的修复期。"
  }
}
```

### 说明

1. `flow_label`
   - 回答资金方向

2. `volume_regime`
   - 回答短线是否放量/缩量

3. `ratio_20 / ratio_60`
   - 回答相对位置

4. `slope`
   - 回答热度变化方向

5. `heat_phase`
   - 回答这是过热、冰点、修复还是衰减

### 关键字段释义

以下以示例值说明，不代表固定阈值：

1. `main_flow_today_ratio: 0.0021`
   - 定义：`main_in_flow_today / circular_market_val`
   - 含义：当日主力净流入占流通市值约 `0.21%`
   - 作用：衡量主力当日净流入的相对力度，而不是看绝对金额

2. `main_flow_5d_ratio: 0.0078`
   - 定义：`main_in_flow_5d / circular_market_val`
   - 含义：近 5 日主力累计净流入占流通市值约 `0.78%`
   - 作用：看短期主力是否在持续堆积筹码

3. `turnover_ratio_20: 0.84`
   - 定义：`target_turnover / ema20(turnover)`
   - 含义：当前成交额只有过去 20 日均值的 `84%`
   - 作用：判断当前成交承接相对近 1 个月是偏弱还是偏强

4. `turnover_ratio_60: 1.12`
   - 定义：`target_turnover / ema60(turnover)`
   - 含义：当前成交额约为过去 60 日均值的 `112%`
   - 作用：判断当前成交承接相对近 3 个月是否已恢复到均值之上

5. `turnover_rate_ratio_20: 0.91`
   - 定义：`target_turnover_rate / ema20(turnover_rate)`
   - 含义：当前换手率约为近 20 日均值的 `91%`
   - 作用：判断筹码交换效率相对近 1 个月是否偏弱

6. `turnover_rate_ratio_60: 1.18`
   - 定义：`target_turnover_rate / ema60(turnover_rate)`
   - 含义：当前换手率约为近 60 日均值的 `118%`
   - 作用：说明虽然短线不算热，但相对近 3 个月已有一定修复

### 如何组合解读这组示例

若出现：

1. `turnover_ratio_20 < 1`
2. `turnover_ratio_60 > 1`
3. `turnover_rate_ratio_20 < 1`
4. `turnover_rate_ratio_60 > 1`

则更可能意味着：

1. 当前热度相对最近 1 个月不算强
2. 但相对过去 3 个月已经不弱
3. 这通常对应“阶段性修复中”，而不是极端过热
4. 最终仍需结合 slope 和价格位置，才能判断是修复、衰减还是中性整理

## 10. 单股评分建议

本文档服务于 `stock_score` 的计算，可拆成三部分：

1. **资金方向分**：10分
   - 主力与整体流向是否共振
   - 多周期资金流是否同向

2. **承接质量分**：10分
   - 成交额、换手率相对 20 日 / 60 日基线是否有效抬升

3. **热度结构分**：10分
   - 热度导数是增强、衰减还是冰点修复
   - 是否处于不宜追涨的位置

### 一个重要约束

若出现以下情况，应下调 `stock_score`：

1. 价格上涨但主力净流持续为负
2. 热度极高但导数转弱
3. 放量发生在明显高位压力区
4. 盘中数据不完整却误把当天换手率纳入正式比较

## 11. Prompt 写法建议

在给 LLM 的输入中，不建议只传：

```text
主力净流入 xx 万，散户净流入 xx 万
```

而应升级为：

```text
【个股资金流与流动性承接】
- 主力净流（当日/5日/10日/90日）：...
- 整体净流（当日/5日/10日/90日）：...
- 成交额相对20日/60日：...
- 换手率相对20日/60日：...
- 热度变化方向：升温 / 降温 / 冰点修复 / 过热衰减
- 短线量能状态：放量 / 中性 / 缩量
- 当前结论：主力托底 / 主力出逃 / 散户追高 / 抛压衰减 / 谷底修复候选
```

同时约束模型：

1. 不能把“高热度”直接写成利多
2. 不能把“低热度”直接写成利空
3. 必须结合价格位置解释资金与量能

## 12. 最小实现路径

第一阶段只做最小闭环：

1. 保留现有 `main_in_flow / in_flow` 框架
2. 引入 `turnover / turnover_rate`
3. 增加 `20/60` 相对基准
4. 增加 `15:00` 后才用当日累计量能的约束
5. 保留 `放量 / 中性 / 缩量` 三档输出

第二阶段再做：

1. 热度导数
2. 冰点修复 / 过热衰减的结构识别
3. 与价格趋势标签的更精细联动

---

## 13. 最终原则

这套方案最终要守住四条原则：

1. **方向和承接分开**
   - 资金流不等于流动性

2. **短线与中期分开**
   - `5/20` 负责短线 regime
   - `20/60` 负责 1 月 / 3 月相对位置

3. **热度和导数分开**
   - 不能只看高低，还要看升降

4. **中性不过拟合**
   - 只有明显偏离才打强标签

只要这四条不被破坏，这个模块才能真正从“资金流描述器”升级成“可交易的个股资金与流动性承接中间层”。
