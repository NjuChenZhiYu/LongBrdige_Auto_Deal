# 个股资金流与流动性承接策略设计

## 1. 目标

本文用于约束单股研报中的“流动性 25%”因子。它不是独立给出买卖结论，而是为 `llm_analyst.py` 的五因子评分提供结构化输入：

1. **资金方向**：主力与整体资金是流入还是流出。
2. **短线量能**：当前是否明显放量、缩量或中性。
3. **流动性承接**：成交额和换手率相对历史基线是否有真实支撑。
4. **价格位置联动**：同样的放量/缩量，要结合趋势、筹码区和多周期位置解释。

现阶段代码已经实现的是 `single_stock_math_calculate.py::calculate_ema_derivatives()` 中的短线量能 regime：`放量 / 中性 / 缩量`。本文档以该算法为准，同时定义后续补齐 20/60/180 日流动性相对位置的最小输入契约。

---

## 2. 为什么原方案不够

旧方案的优点是简单、直观，但存在三个明显问题：

1. **只看净流方向，忽略承接质量**
   - `main_in_flow > 0` 只能说明主力净额为正，不代表市场就有足够承接。
   - 如果成交额和换手率都很低，所谓“流入”可能只是极小流通盘里的局部撮合，并不足以支持趋势。

2. **只看短线量能，忽略相对位置**
   - 同样是 `10 亿成交额`，对腾讯和对小市值新股的含义完全不同。
   - 同样是 `5% 换手率`，对日常高换手题材股和低换手权重股的含义也完全不同。
   - 必须把当前值与过去 `20日 / 60日 / 180日` 进行比较，才能知道这是短线波动、阶段修复，还是长期流动性重估。

3. **把短线放量误当成流动性改善**
   - 当前代码的 `5/20` 更适合识别短线量能偏离。
   - 但单股综合评分里的“流动性 25%”需要更稳定的成交额、换手率相对基线。
   - 因此 `5/20` 不废弃，但不承担中期流动性打分的全部职责。

## 3. 模块边界

本文只讨论**个股层**的资金与流动性承接，不覆盖市场层和板块层流动性。

边界建议如下：

1. `docs/Strategy/market_capital_flow.md`
   - 负责市场层、板块层、个股层的总框架
   - 负责 `market_score / sector_score / stock_score` 的上游定义

2. 本文档 `docs/Strategy/capital_flow_strategy.md`
   - 负责个股层的“资金方向 + 短线量能 + 流动性承接”的具体口径
   - 作为单股研报中“流动性 25%”的来源文档

换句话说，本文件不是完整 `stock_score` 方法论，而是五因子框架中流动性部分的说明书。

## 4. 核心原则

### 4.1 不把“资金净流”误当成“流动性”

个股分析必须把两类问题拆开：

1. **资金方向**
   - 看 `main_in_flow`、`in_flow`
   - 回答：钱是净流入还是净流出

2. **流动性承接**
   - 看 `turnover`、`turnover_rate`
   - 回答：有没有足够的真实成交承接

结论：

- `资金流` 负责判断“方向”
- `成交额 + 换手率` 负责判断“承接质量”

缺一不可，不能互相替代。

### 4.2 不用单一指标做线性判断

以下几种线性推理都容易出错：

1. 成交额高 = 买入
2. 换手率高 = 强势
3. 主力净流入 = 必涨
4. 冰点 = 必卖
5. 热度高 = 必追

更合理的判断方式是：

1. 先看方向
2. 再看承接
3. 再看相对位置
4. 最后结合价格位置解释

## 5. 输入数据与字段来源

## 5.1 资金流字段

历史多日资金流来自富途 `get_capital_flow(...)`：

1. `in_flow`
2. `main_in_flow`
3. `capital_flow_item_time`
4. `super_in_flow`
5. `big_in_flow`
6. `mid_in_flow`
7. `sml_in_flow`

字段名以富途 API 为准：主力净流字段是 `main_in_flow`，不是 `main_flow_in`。

### 用途

1. 重点判断**整体净流入/净流出方向**，即 `in_flow`
2. 辅助判断**主力净流方向**，即 `main_in_flow`
3. 判断整体与主力是否一致
4. 粗粒度识别是主力托底、主力出逃，还是市场分歧

### 当前代码口径

当前港股单股分析使用两种口径：

1. **历史 5/10/90 日**
   - 数据来源：`get_capital_flow(..., period_type=DAY)`
   - `main_in_flow_hkd = sum(main_in_flow)`
   - `total_in_flow_hkd = sum(in_flow)`
   - 对应 `hk_single_stock_indicator.py::_aggregate_hk_capital_flow_from_df()`

2. **当日实时**
   - 数据来源：`get_capital_distribution(...)`
   - `main_in_flow_today = (capital_in_super + capital_in_big) - (capital_out_super + capital_out_big)`
   - `total_in_flow_today = main_net + mid/small_net`
   - 对应 `hk_single_stock_indicator.py::get_today_capital_flow()`

因此文档和 prompt 中的“主力净流”含义是：

- 历史窗口：富途原生 `main_in_flow`
- 当日实时：用超大单和大单流入/流出合成的主力大单净流

### 关于 `super/big/mid/sml` 的使用原则

这几个字段可以保留，但在策略上应**弱化权重**，原因是：

1. 主力、游资、机构完全可能拆分成多个账户下单
2. 单笔口径并不稳定，容易被“拆单行为”污染
3. 若过度依赖 `big / mid / sml` 的静态拆分，容易把执行层噪声误判成真实资金属性

因此建议：

1. **主判断**
   - `in_flow`
   - `main_in_flow`

2. **辅助判断**
   - `super_in_flow / big_in_flow / mid_in_flow / sml_in_flow`

3. **不建议**
   - 仅凭 `big_in_flow` 或 `mid_in_flow` 的正负，直接给出“机构进场 / 散户出逃”结论

换句话说，本模块默认采用“**先看 in 还是 out，再看 main 是否同向**”的粗粒度判断，不把订单大小拆分当作绝对真相。

## 5.2 成交承接字段

来自快照或 K 线：

1. `turnover`
2. `turnover_rate`
3. `volume`
4. `close`
5. `high`
6. `low`

### 用途

1. `turnover` 看绝对成交规模
2. `turnover_rate` 看筹码交换效率
3. `volume` 仍可保留作为辅助项，但不再作为唯一量能标准

---

## 6. 今日数据使用边界

这是本模块最重要的实务约束之一。

### 6.1 港股当天 `turnover / turnover_rate` 不能过早纳入正式比较

港股盘中累计成交额和累计换手率，在收盘前具有天然不完整性：

1. 早盘数据天然偏低
2. 午盘前后不可横向比较
3. 尾盘放量是港股常见现象

因此，盘中若直接把“今天的成交额/换手率”与历史日线完整数据做比较，会系统性低估热度。

### 6.2 统一规则

建议沿用现有逻辑：

1. 港股 `15:00` 前：
   - 不使用当天 `turnover`
   - 不使用当天 `turnover_rate`
   - 默认用最近一个完整交易日作为比较目标

2. 港股 `15:00` 后：
   - 若 `update_time / data_date / last_trade_time` 确认是当日
   - 才允许把当天 `turnover / turnover_rate` 纳入正式对比

### 6.3 设计含义

这不是“数据保守”，而是为了防止以下误判：

1. 早盘误判成缩量
2. 午盘误判成流动性枯竭
3. 盘中把尚未完成的换手率错误解释成“无人接盘”

## 7. 当前已实现算法：短线量能 regime

`calculate_ema_derivatives()` 当前承担两件事：

1. 用价格 EMA 计算当日趋势标签：`tag`
2. 用成交量/成交额 EMA 计算短线量能标签：`volume_regime`

### 7.1 量能字段选择

代码按优先级选择量能代理：

1. `turnover`
2. `amount`
3. `volume`

优先使用成交额，是因为成交额比成交量更能反映真实盘口承接。只有在没有成交额字段时，才退回到 `volume`。

### 7.2 目标值与基线

量能侧默认使用完整交易日：

1. 若调用方传入有效 `current_turnover/current_volume`：
   - `target_vol = current_turnover/current_volume`
   - `baseline_vol = 历史完整日序列`

2. 若没有传入有效盘中量能：
   - `target_vol = 最近一个完整交易日`
   - `baseline_vol = 更早的完整交易日序列`

这对应第 6 节的规则：港股 `15:00` 前不把当天累计成交额/换手率纳入正式比较。

### 7.3 现有短线指标

当前返回三个短线量能比值：

1. `volume_ratio_target_ema5 = target_vol / ema5(baseline_vol)`
2. `volume_ratio_target_ema20 = target_vol / ema20(baseline_vol)`
3. `volume_ratio_ema5_ema20 = ema5(baseline_vol) / ema20(baseline_vol)`

其中：

- `target/ema5`：判断当前目标相对最近几日是否极端偏离
- `target/ema20`：判断当前目标相对近 1 个月是否显著偏离
- `ema5/ema20`：观察短线量能中枢是否已经抬升或回落

### 7.4 放量/缩量判定

当前只输出三档：

1. `放量`
2. `中性`
3. `缩量`

触发逻辑是“双确认 + 短期极端”：

1. `放量`
   - `target/ema20` 和 `target/ema5` 同时达到放量阈值；或
   - `target/ema5` 达到短期极端放量阈值

2. `缩量`
   - `target/ema20` 和 `target/ema5` 同时达到缩量阈值；或
   - `target/ema5` 达到短期极端缩量阈值

3. `中性`
   - 其余情况不强行解释

这个设计应保留。中性状态信息含量有限，过度拆分会放大量化噪声。

### 7.5 与价格标签的关系

`tag` 本身只由价格 EMA 决定，不受量能影响。`volume_regime` 只在最后一步与 `tag` 组合成 `tag_combined`：

1. `主升浪加速 + 放量`：突破有效性更高，但仍要防追高
2. `主升浪降速 + 放量`：更需要警惕高位派发
3. `主跌浪加速 + 放量`：破位或抛压释放风险更高
4. `跌势放缓 + 缩量`：更像抛压衰减，但仍需资金确认
5. `短期转多 + 放量`：转强可信度提高
6. `短期转空 + 缩量`：可能是弱回调或洗盘，但必须看中期位置

结论：当前 `5/20` 算法适合解释“短线量价”，不适合作为单股综合评分中“流动性 25%”的唯一依据。

## 8. 待补齐算法：流动性 25% 输入

单股综合评分的流动性因子建议由三部分构成：

1. **资金方向**
   - 当日 / 5日 / 10日 / 90日主力净流
   - 当日 / 5日 / 10日 / 90日整体净流
   - 主力与整体是否同向

2. **成交额承接**
   - `turnover_ratio_20 = target_turnover / ema20(turnover)`
   - `turnover_ratio_60 = target_turnover / ema60(turnover)`
   - `turnover_ratio_180 = target_turnover / ema180(turnover)`

3. **换手率承接**
   - `turnover_rate_ratio_20 = target_turnover_rate / ema20(turnover_rate)`
   - `turnover_rate_ratio_60 = target_turnover_rate / ema60(turnover_rate)`
   - `turnover_rate_ratio_180 = target_turnover_rate / ema180(turnover_rate)`

### 8.1 周期含义

1. `20日`
   - 近 1 个月热度
   - 容易受短期题材和公告扰动影响
   - 阈值应更敏感，用于捕捉近期升温或退潮

2. `60日`
   - 近 1 个季度常态
   - 适合作为阶段性流动性恢复或退潮的主参考
   - 阈值居中，用于判断阶段承接是否稳定

3. `180日`
   - 近半年长期底色
   - 用于判断标的是长期冷门、阶段重估，还是持续高关注
   - 阈值应更宽，只做长期流动性底色判断

### 8.2 偏低 / 安全 / 偏高分层

这里的比值只和自身历史比较，不做横向比较：

- `turnover_ratio_N = target_turnover / emaN(turnover)`
- `turnover_rate_ratio_N = target_turnover_rate / emaN(turnover_rate)`

其中 `target` 遵守第 6 节的数据口径：15:00 前使用最近完整交易日，15:00 后且快照确认当日才使用当天累计值。

第一版不需要复杂打分，先把每个 ratio 分成三档：

| 窗口 | 偏低 | 安全区 | 偏高 |
| --- | --- | --- | --- |
| `20日` | `< 0.80` | `0.80 - 1.25` | `> 1.25` |
| `60日` | `< 0.70` | `0.70 - 1.40` | `> 1.40` |
| `180日` | `< 0.60` | `0.60 - 1.60` | `> 1.60` |

解释原则：

1. `20日` 更敏感，轻微偏离就应提示近期升温/降温。
2. `60日` 是主判断，决定阶段性承接是否健康。
3. `180日` 只判断长期底色，不因短期事件频繁翻转。
4. `偏高` 不自动利多，可能是有效换手，也可能是高位派发。
5. `偏低` 不自动利空，低位缩量可能是抛压衰减，高位缩量可能是承接不足。

### 8.3 成交额与换手率组合解释

成交额和换手率必须一起看，才能组织出可交易的流动性结论：

1. **成交额偏高 + 换手率偏高**
   - 绝对资金和筹码交换都活跃。
   - 低/中位更像增量承接或换手确认；高位更要警惕派发。

2. **成交额偏高 + 换手率安全/偏低**
   - 大额资金参与，但筹码交换不极端。
   - 对大市值股更友好，可能是机构型承接；若价格高位滞涨，则要防大资金对倒或出货。

3. **成交额安全/偏低 + 换手率偏高**
   - 绝对资金不强，但筹码交换很快。
   - 小市值或低价股常见，偏情绪换手，不宜直接视为强承接。

4. **成交额安全 + 换手率安全**
   - 流动性健康但不极端。
   - 若资金方向为正、趋势筹码配合，是最适合稳健打分的状态。

5. **成交额偏低 + 换手率偏低**
   - 交易冷清，资金流信号需要打折。
   - 低位可能是抛压衰减，高位可能是无人接力。

### 8.4 与短线量能 regime 的关系

成交额/换手率相对 `20/60/180` 与短线量能 `volume_regime` 有重叠，但不是同一个东西：

1. **短线量能 regime**
   - 来源：`calculate_ema_derivatives()` 的 `5/20`。
   - 回答：当前目标成交是否相对短期基线明显放大或萎缩。
   - 用途：解释 `tag_today` 的短线量价含义。

2. **成交额/换手率承接**
   - 来源：`turnover_ratio_20/60/180` 与 `turnover_rate_ratio_20/60/180`。
   - 回答：当前成交规模和筹码交换效率处在近 1 月、1 季度、半年什么位置。
   - 用途：给单股综合评分中的“流动性 25%”提供结构性依据。

因此：

- `volume_regime = 放量` 只能说明短线发生明显偏离，不能单独证明流动性健康。
- `20/60/180` 才能说明这次放量是短期脉冲、阶段修复，还是长期重估。
- 若两者一致，例如短线放量且 `20/60` 成交额、换手率都偏高，说明热度确认度更高。
- 若两者背离，例如短线放量但 `60/180` 仍偏低，说明更可能是短期事件脉冲。

### 8.5 跨周期组合解释

跨周期解释直接使用 8.2 的三档结果，不再新增判断体系。先分别给成交额和换手率打 `偏低 / 安全 / 偏高`，再看 20/60/180 的排列。

1. **短期偏高 + 中期偏高 + 长期偏高**
   - 当前活跃度已经高于近 1 月、1 季度和半年基线。
   - 这是强流动性状态，但不自动利多；低/中位更像增量承接，高位更像加速换手或派发风险。

2. **短期偏高 + 中期偏高 + 长期安全/偏低**
   - 阶段性热度明显修复，但长期底色尚未完全重估。
   - 若资金方向同步转正，偏“修复确认”；若主力流出，偏“事件脉冲或散户追高”。

3. **短期安全/偏低 + 中期偏高 + 长期偏高**
   - 长中期仍有关注度，但短线正在降温。
   - 若价格在高位，可能是热度衰减；若价格回到支撑区，可能是健康降温。

4. **短期偏低 + 中期偏低 + 长期偏低**
   - 三个周期都低于自身历史基线，说明交易活跃度整体冷清。
   - 这有两种解释：低位可能是“卖不动/抛压衰减”，高位或破位后可能是“缺乏承接/无人接力”。
   - 因此必须结合趋势筹码：低位缩量 + 主力不再流出，可以给左侧观察分；高位缩量 + 资金转弱，应下调流动性分。

5. **短期偏低 + 中期安全 + 长期安全**
   - 只是短线降温，不能直接判断流动性恶化。
   - 更适合解释为等待新催化或技术整理。

6. **短期偏高 + 中期安全 + 长期安全**
   - 短线出现脉冲，但尚未改变中长期流动性状态。
   - 需要观察后续 3-5 个交易日能否传导到 20/60 日承接。

这些规则只服务于解释，不直接等同买卖信号。最终必须和趋势筹码、基本面、估值、催化一起打分。尤其是“三周期偏低”，不能简单写成利空：它既可能是低位卖压枯竭，也可能是高位承接消失。

## 9. 给 `llm_analyst.py` 的 Prompt 契约

单股研报的总分应明确使用五因子：

1. 基本面：30%
2. 关联估值：20%
3. 流动性：25%
4. 趋势筹码：15%
5. 事件催化：10%

其中流动性输入建议单独成块，不再混在“筹码”里：

```text
【资金流与流动性】
- 资金方向：
  - 当日实时：主力大单净流 = (特大单流入 + 大单流入) - (特大单流出 + 大单流出)，整体净流 = 主力净流 + 中小单净流
  - 历史窗口：5日/10日/90日主力净流 = sum(main_in_flow)，整体净流 = sum(in_flow)
- 短线量能：放量/中性/缩量，来自 tag_today 的 volume_regime
- 成交额承接：相对20/60/180日均值，并标注偏低/安全/偏高
- 换手率承接：相对20/60/180日均值，并标注偏低/安全/偏高
- 数据口径：港股15:00前使用最近完整交易日；15:00后且快照确认当日，才使用当天成交额/换手率
```

实现到 `llm_analyst.py` 时，这个块可以替代当前的【筹码与流动性档案】资金行；筹码信息应留在“趋势筹码”块里，由 POC、筹码分布、布林位置、bias20 和 30/90/180 日空间位置承担。

模型输出时必须遵守：

1. 不能把主力净流入直接等同于看多
2. 不能把放量直接等同于突破有效
3. 不能把低换手直接等同于无人承接
4. 必须说明流动性在 25 分中大致贡献多少分
5. 必须结合趋势筹码判断放量/缩量发生在低位、中位还是高位
6. 必须区分“短线量能偏离”和“中期流动性承接”，不能重复计分

## 11. 最终原则

1. **资金方向和流动性分开**
   - 净流入说明方向，不说明承接是否充分

2. **短线量能和中期流动性分开**
   - `5/20` 负责短线 regime
   - `20/60/180` 负责流动性 25% 的相对位置

3. **成交额和换手率必须同时看**
   - 成交额看绝对资金承接
   - 换手率看筹码交换效率

4. **量能必须结合位置**
   - 低位缩量可能是抛压衰减
   - 高位放量可能是派发
   - 中位放量可能是换手确认

5. **中性不过拟合**
   - 只有明显偏离才打强标签
   - 中性状态不强行编故事
